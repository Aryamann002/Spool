# Figma

## Overview

Figma is the mainstream collaborative design editor: a browser-first, multiplayer design tool with a
desktop wrapper, widely treated as the de-facto standard UI/UX design environment. It is the reference
point for mainstream design-editor conventions because the majority of UI designers encounter design
through it, and because its UI conventions (blue selection, tool lifecycle, keyboard layout) have become
shared vocabulary across the industry.

Positioning evidence: the product spans Figma Design (UI/UX), FigJam (whiteboarding), Slides,
Sites (published sites), Buzz (social/marketing assets), Make (prompt-to-app), Motion, Dev Mode
(handoff), and MCP Server (agent integration). This is a *platform* expansion, not a single editor.
[DOCUMENTED — figma.com product pages and help centre article index]

Confidence: high on documented behaviour; medium on anything about internals.

## Product Philosophy

**Everything is a layer.** The help centre consistently says "Every shape, text object, or image you
add to the canvas has its own layer." The word *layer* is used for objects generally, not only for
containers. [DOCUMENTED — "Adjust alignment, rotation, position, and dimensions"]

**Explicit spatial model over implicit.** Position (X/Y of the bounds' top-left corner), dimension
(W/H), rotation (degrees), constraints, and auto layout are all first-class, inspectable properties
rather than emergent results of dragging. [DOCUMENTED]

**Everything can be generated by keyboard.** Figma ships a crosshair cursor placement mode, a
keyboard-only box-selection tool, an actions menu (`Cmd/Ctrl+/`), and 16 keyboard layouts.
"DOCUMENTED — "Use Figma products with a keyboard", "Select keyboard layout""]

**The document is not the product; the system is.** Variables, modes, collections, libraries, branches,
version history, Dev Mode code export, and MCP all exist to make designs legible to other systems.
[DOCUMENTED]

Explicit product-positioning statement observed: *"Keyboard controls are enabled by default for all
users and cannot be disabled."* [DOCUMENTED] This is an unusual and deliberate accessibility posture.

## Interaction Model

Figma does not publish an explicit state chart. Behaviour is documented per-feature. Reconstructed
interaction phases below are [INFERRED] from documented behaviour; they are not stated by Figma.

### Shape tool lifecycle (reconstructed) [INFERRED]

```
idle (tool active, no pointer)
  -> pointer down on empty canvas
     -> pointing (threshold not crossed)
        -> pointer up ............ => create default-size shape (click-to-place), select it
        -> drag past threshold
           -> dragging
              -> pointer up ...... => commit sized shape, select it, remain on the tool
              -> Escape ........... => cancel, no document change, no history entry
  -> pointer down on existing shape
     -> hit test decides: top-level frame/group vs. nested child (see Selection)
```

Click-to-place vs. drag-to-size is DOCUMENTED for text (single click ⇒ auto width; click-and-drag ⇒
fixed size). It is OBSERVED for rectangles/ellipses/frames that a click places a default-sized shape.

## Selection

Selection is one of Figma's most heavily documented areas, and the documentation is unusually explicit
about the three-way distinction between **what is selected**, **what is being edited**, and **what the
active tool is**.

### The parent-by-default rule

> "When you click on an object that is part of a group or frame, we'll select the parent by default.
> Double-click on the object - or press the enter key - to select one level of nesting down. Repeat
> this process until you select the correct child elements."

[DOCUMENTED — "Select layers and objects"]

This is a **scope stack**: Figma keeps an implicit "current selection depth" that descends on
double-click/Enter and ascends on Escape.

### Deep select

> "Hold down the modifier key to select the top-level frame or a nested layer or object by clicking it
> on the canvas. Mac: ⌘ Command / Windows: Control"

[DOCUMENTED] So `Cmd/Ctrl`-click bypasses the parent-by-default rule and selects the actual hit object.

### Keyboard traversal (all DOCUMENTED)

| Key | Action |
|---|---|
| `Enter` | Select child (one level down) |
| `Shift Enter` | Select parent |
| `Tab` | Select next sibling |
| `Shift Tab` | Select previous sibling |
| `Cmd/Ctrl A` | Select all on canvas |
| `Cmd/Ctrl Shift A` | Select the **inverse** of the current selection |
| `Option/Ctrl+A` (`Alt Ctrl A` Win) | Select all **matching** layers (same name, same structure) |
| `Esc` | Deselect all / exit nesting scope |

Figma also offers a **Select Layer menu** (right-click ⇒ Select layer) that lists every layer under the
cursor in Layers-panel order, including hidden layers toggled visible and **locked layers** (marked with
a padlock). Locked layers cannot be left-clicked but *can* be selected this way. [DOCUMENTED]

Locked layers cannot be selected by normal left-click. [DOCUMENTED]

### Marquee

- Drag on empty canvas ⇒ selection marquee, fully-contained objects are selected. [DOCUMENTED]
- `Cmd/Ctrl`-drag marquee ⇒ selects *nested* objects rather than their parents. [DOCUMENTED]
- Figma explicitly warns: *"It's possible to select nested objects without selecting the parent
  object. This is something to be mindful of, especially when selecting objects to move them!"*
  [DOCUMENTED] — an admission that selection can produce semantically surprising results.
- `Shift`-click a selected object removes it from the selection (toggle). [DOCUMENTED]
- Marquee intersection mode is **not** documented as configurable in Figma (Affinity has one — see
  `Affinity` product file).

### Multi-select consequences

> "When you select more than one layer, you can access Selection Colors in the right sidebar. This
> allows you to update individual Fills, Styles and Strokes in a mixed selection."

[DOCUMENTED] This is the "mixed value / common value" pattern (see `interaction/transformation.md`).

### Edit-only view

Viewers see their selection outlined in solid purple, with the **parent** outlined dashed, and the
selected layer name plus parent component name surfaced in the Properties panel. [DOCUMENTED] Evidence
that selection has a distinct "inspected" presentation separate from the editable selection.

## Transformation

Everything in this section is DOCUMENTED from "Adjust alignment, rotation, position, and dimensions"
unless noted.

### Position

- X/Y refer to the **top-left corner of the layer's bounds**.
- If the layer is rotated, X/Y remain based on the *original unrotated* top-left corner.
- Numeric fields accept inline arithmetic (`- + * / ^ ( )`), applied before or after the existing value.

### Dimension and aspect ratio

- Drag edges/corners; W/H fields in the sidebar.
- "Lock aspect ratio" is a per-layer boolean, toggleable in Layout/Auto layout section.
- `Ctrl/Cmd` while dragging temporarily disables lock; `Shift` while dragging temporarily enables it —
  and the change is **not persisted** on release.
- Aspect ratio cannot be set on child layers of component instances; it must be set on the main component.
- With min/max constraints and a locked aspect ratio, setting a minimum on one axis derives a
  proportional minimum on the other (e.g. 1:2 ratio + min height 100 ⇒ min width 200).

### Rotation

- Positive angles go counter-clockwise toward 180°; beyond 180° Figma counts down to -180°.
- Default rotation origin is the **horizontal and vertical centre of the current selection**.
- `Option R` / `Alt R` reveals a draggable rotation origin per object.
- `Shift` while rotating snaps to 15° increments.
- Figma does **not** rotate effects (shadows etc.).
- Dev Mode note: Figma stores rotation as the CSS `transform: rotate()` property, whose sign convention
  is inverted relative to the Figma UI (`90` in Figma ⇒ `transform: rotate(-90deg)`).
- Flip H/V use the CSS `matrix()` transform; once flipped, a later rotation still uses `matrix()`.

### Nudge

- Arrow keys nudge by "small nudge" (default 1); `Shift`+arrow uses "big nudge" (default 10).
- Both values are user-configurable and resolution-independent.
- With nothing selected, arrow keys **pan** the canvas instead, and `Shift`+arrow pans faster, with the
  distance dependent on zoom. [DOCUMENTED]

### Alignment

`Alt W/A/S/D` = top/left/bottom/right; `Alt V` = vertical centres; `Alt H` = horizontal centres.
`Shift` + clicking the alignment control aligns as a group to the parent frame. [DOCUMENTED]

Single selected object aligns **to its parent**; multiple selected objects align **to each other**.
[DOCUMENTED]

### Distribute vs Tidy up

Figma has two distinct distribution behaviours, and the documentation is precise about the difference:

- **Distribute**: equalises spacing *within the original selection bounds*; outermost objects retain
  position. One axis at a time.
- **Tidy up** (smart selection): reorganises the selection into rows/columns. On a 2D selection it
  aligns to the **top-left corner of the selection** and adjusts both axes; on a 1D selection it works
  along the axis the objects overlap on. It also requires objects to *overlap* on the other axis.

Both report a "space between" value computed as the **mode** (most common gap). With pixel snap on,
Figma allows 1px of rounding; with it off, distribute can produce fractional gaps like 7.5. [DOCUMENTED]

[INFERRED] "Tidy up" is a *layout* operation that changes relative positions; "Distribute" is a
*spacing* operation that preserves ordering. Treating them as one "align/distribute" command would lose
this distinction.

## Tools

Figma's tool set (DOCUMENTED through the tool bar and help articles):

Move, Frame, Section, Slice, Shape (rectangle/ellipse/line/polygon/star), Pen, Pencil, Text,
Hand, Comment, **Scale**, **Slice**, **Boolean operations** (as a group: union/subtract/intersect/
exclude), **Mask**, **Flatten**, **Outline stroke**, **Create component / Create component set**,
**Combine as variants**, **Group / Frame selection**, **Slice**, and (in newer surfaces) **Fill**,
**Connector / Arrow**.

Figma does **not** publish a state chart, a "tool lifecycle" article, or a tool-lock concept in the
tldraw sense. [OBSERVED] In practice, shape tools **stay active after creating a shape** (you can draw
several rectangles in a row), whereas Pen and Text return differently. This inconsistency is a known
community complaint. [THIRD-PARTY — Figma forum threads]

Notably: Figma provides a **Boolean operations** command that *consumes* selected shapes and produces a
single result, and a **Flatten** command that converts a hierarchy to a single vector path. These are
destructive top-level document operations with distinct undo semantics. [DOCUMENTED]

Also notable: Figma **does not document a Node Tool for path editing in general use**; vector point
editing is entered by double-clicking a vector/pen object, which switches to a direct-selection-like
mode. [OBSERVED / THIRD-PARTY] "Snap to geometry: *Used only in vector edit mode*" is DOCUMENTED, which
confirms a distinct "vector edit mode".

## Text

Deeply documented. Key facts:

- **Text layers are created with an explicit creation intent.** Click-to-place ⇒ **auto width**. Click-
  and-drag ⇒ **fixed size**. [DOCUMENTED — "Adjust text dimensions and resizing"]
- Auto width grows horizontally; Enter inserts an explicit newline. Wrap style (Balance / Pretty) has
  **no effect** on auto-width layers. [DOCUMENTED]
- Manually resizing a text layer's box switches its resizing property to **Fixed size**. [DOCUMENTED]
- **Vertical text alignment only works on fixed-size text layers**; auto-width/auto-height layers ignore
  it. [DOCUMENTED — "Explore text properties"]
- The **Scale tool** changes the bounding box *and* the font size together, which can produce fractional
  font sizes and subpixel bounds; Figma explicitly recommends using Font size instead. [DOCUMENTED]
- Text supports max lines; a text layer **cannot** have both a max height and a numeric max lines —
  setting one clears the other. [DOCUMENTED — auto layout guide]
- Text in auto layout is recommended to be auto-width; fixed-size text can overlap siblings. [DOCUMENTED]
- Number variables can drive font size, weight, line height, letter spacing, paragraph indent, and
  paragraph spacing — meaning **typography properties are bindable**. [DOCUMENTED]

Text editing: double-click enters edit mode with a caret; ranges are selected by drag or shift-click;
Escape commits. [OBSERVED / DOCUMENTED via auto-layout "single-click vs click-and-drag" framing]

## Drawing

- **Pen tool**: creates Bézier paths by click (corner point) and click-drag (smooth point). [OBSERVED /
  well-documented in community tutorials; Figma help covers "vector paths" but not the pen lifecycle in
  depth]
- **Pencil tool**: freehand → vector conversion. Figma offers a smoothing/fitting step. [DOCUMENTED
  existence; details OBSERVED]
- Keyboard creation is explicitly *not* supported for lines, vector paths, connectors, and tables.
  [DOCUMENTED — "Use Figma products with a keyboard"] This is an admission that those tools are
  irreducibly multi-click.
- Freehand input in Figma is stored as vector geometry, not as a raster or an unbounded point stream.
  [INFERRED from the fact that freehand strokes are stroke-editable and can be node-edited]

Key architectural facts:

1. **Frames are the universal container.** Auto layout, components, and instances are all *frames with
   extra properties*. [DOCUMENTED — "As components are frames, you can add auto layout to them"]
2. **Groups are second-class**: no own bounds, cannot take constraints, constraints apply to children.
   [DOCUMENTED]
3. **Instances are live references.** "Instances are linked to the main component and receive any
   updates made to the component." [DOCUMENTED]
4. **Styles and variables are different kinds of indirection.**
   - "A style is great for creating a composite of values. Also, styles cannot be used in other styles
     or variables."
   - "Variables can be used to create multiple modes ... variables can be applied to styles and other
     variables."
   [DOCUMENTED — "Overview of variables, collections, and modes"]
   [INFERRED] Figma's style system is therefore a *one-level* named-bundle indirection, while variables
   are a *composable, aliasable, mode-switchable* indirection. They solve different problems and are not
   interchangeable.

## Hierarchy

- Order is expressed as layer order in the Layers panel; depth (Z) is described as "corresponding to an
  object's z-index". [DOCUMENTED]
- **Layer order behaves differently inside auto layout.** "Layer order works the opposite way inside an
  auto layout frame. This is because auto layout wasn't designed to support layers that overlap."
  Changing order inside auto layout changes *layout position*, not z-order. [DOCUMENTED]
- Groups inherit bounds; frames do not. Reparenting changes coordinate basis implicitly.
- "It's possible to select nested objects without selecting the parent object" — hierarchy and selection
  are deliberately decoupled. [DOCUMENTED]

## Components / Reuse

- **Main component** defines properties; **instance** is a linked copy that "receive[s] any updates made
  to the component". [DOCUMENTED]
- **Overrides** are per-instance deviations. Reset removes overrides; detach converts an instance to
  plain layers. [DOCUMENTED]
- **Component properties** can be created for any main component or variant and applied to *nested*
  layers. [DOCUMENTED — "Explore component properties"] This is important: component properties reach
  into the component's internals by path.
- **Variants / component sets** group a component into a set with a variant property. [DOCUMENTED]
- **Libraries** publish components and styles to team libraries, shared across files. [DOCUMENTED]
- **Matching layers**: "identical layers that exist across more than one frame or group", selectable
  across the file with `Alt+Cmd+A`. [DOCUMENTED] This is a *structural* reuse mechanism separate from
  components — a weak, non-explicit form of instance.

Auto-layout constraints on components are asymmetric: padding and gap can be overridden; **reorder,
add, and delete of layers cannot** (delete only hides the layer). [DOCUMENTED — auto layout guide]

[INFERRED] Figma's instance model is best described as: **a persistent reference to a subtree, plus a
per-instance overlay of property values and visibility flags, plus a variant switch.** It is not a copy
and not a template expansion.

## Layout

Figma supports **three** layout mechanisms side by side:

1. **Absolute positioning** — every object has explicit X/Y. The default.
2. **Constraints** — per-child, per-axis: `Left`, `Right`, `Left and Right`, `Center`, `Scale`
   (horizontally); `Top`, `Bottom`, `Top and bottom`, `Center`, `Scale` (vertically). Default `Top,Left`.
   - `Scale` means the layer's size and position are a **percentage** of the frame's dimensions.
   - Constraints apply only inside a Frame (not a Group), and only to layers *not* in an auto-layout flow.
   - `Cmd/Ctrl` while resizing ignores constraints for that operation.
   - "Depending on the layer's position, more than one constraint may achieve the same result."
   [DOCUMENTED]
3. **Auto layout** — flexbox-like:
   - Flows: **Vertical**, **Horizontal**, **Grid** (plus "Horizontal and vertical" phrasing for the two
     linear flows).
   - Wrap is available for horizontal/vertical; **vertical wrap is explicitly *not* masonry**:
     "Objects remain in auto-layout order and move to the next column only after the current column
     reaches the frame's available height." [DOCUMENTED]
   - Grid flow supports **span** across rows/columns, with per-row/per-column resizing. [DOCUMENTED]
   - Sizing per axis: **Hug contents** (auto-layout frames only), **Fill container** (children only, not
     top-level frames), **Fixed**, plus **Min** and **Max** that combine with the others.
   - "If any child objects within an auto layout frame are set to `Fill container`, the parent frame will
     no longer hug contents and become Fixed for the axis." [DOCUMENTED] — an implicit dependency.
   - Gap supports a number or **Auto** (`Between`, `Around`, `Evenly`). [DOCUMENTED]
   - Padding: uniform, per-axis, or per-side. [DOCUMENTED]
   - **Ignore auto layout** (formerly "absolute position") excludes a child from the flow while keeping
     it in the frame; the object then behaves like an object in a regular frame and *can take
     constraints*. [DOCUMENTED] — a rename that reveals the concept was always "escaping the flow".

Architectural significance: Figma does not choose one layout system; it provides **three coexisting
systems with explicit precedence and explicit escape hatches**. [INFERRED] Supporting Figma-equivalent
behaviour requires a document model in which a container can simultaneously declare a layout mode, and
each child can either participate in it or opt out and fall back to constraint-based absolute
positioning. This is a materially more complex model than "each frame has an optional layout".

## Styles

- **Styles** are named, reusable bundles: fill, text, effect, grid. Published to libraries.
- **Selection Colors** in the sidebar apply a fill across a mixed selection. [DOCUMENTED]
- **Variables** — six types: Color, Number, String, Boolean, Timing, Easing. [DOCUMENTED]
  - Colour variables carry an optional opacity; a Number variable can drive that opacity and is
    **clamped** (negative ⇒ 0%, >100 ⇒ 100%). [DOCUMENTED]
  - Number variables drive: corner radius (incl. per-corner), dimensions incl. min/max, font family
    (string), size, weight, line height, letter spacing (interpreted as **px, not %**), paragraph
    indent/spacing, layout guides, uniform grid size, row/column count, width/height/margin/offset/gutter,
    padding/gap, shadow x/y/blur/spread, stroke weight (all and per-side), and Motion animation amounts.
  - String variables can set layer **visibility** when the value is `"true"`/`"false"`, and can drive
    **variant instances in prototyping**.
  - Boolean variables drive variant properties and visibility.
  - **Modes** switch the *whole collection's* value set; a layer expresses the value for its current mode.
  - Variables can **alias** other variables of the same type (this is how design tokens are built).
  - Limit: **5,000 variables per collection**.
- **Local vs library**: styles and variables are both publishable to libraries. [DOCUMENTED]
- **Mixed selection**: sidebar shows a value when uniform and a "mixed" state otherwise; setting a value
  applies to all. [DOCUMENTED for Selection Colors; INFERRED for the general pattern]

## History

Two separate mechanisms, often conflated:

1. **Undo/redo** — `Cmd/Ctrl+Z` / `Cmd/Ctrl+Shift+Z`. A drag is one undo step, not hundreds.
   [DOCUMENTED behaviour; internal grouping mechanism is not documented]
2. **Version history** — server-side timeline of file states; viewable, nameable, restorable, and
   "Make a copy"-able. Requires edit access. [DOCUMENTED — "View a file's version history"]
3. **Branching / merging** — "Figma will create an extra checkpoint in the file's version history before
   merging the file, this preserves a record of any other changes made to the main file."
   [DOCUMENTED — "Guide to branching"]

[INFERRED] Version history is snapshot-based and server-side; undo/redo is local and operation-based.
They answer different questions ("what did the file look like on Tuesday" vs "undo my last three
actions") and should not be modelled as one system.

## Keyboard / Input

This is Figma's most distinctive and most documented area.

### Keyboard layout system [DOCUMENTED]

- Default shortcuts assume **US QWERTY**.
- Figma supports **16 selectable keyboard layouts**: Chinese (Pinyin), Danish, Finnish, French AZERTY,
  German QWERTZ, Italian, Japanese (Kana), Korean, Norwegian, Portuguese, Spanish, Spanish (Latin
  America), Swedish, U.K. (Mac/PC), U.S. QWERTY / Generic.
- The preference is **account-wide**, applies to all files, and can be reverted to "Generic".
- **A subset of shortcuts is remapped per layout** — the docs show a table of ~25 actions whose bindings
  change: zoom in/out, show/hide UI, show left sidebar, pixel grid, snap to pixel grid, multiplayer
  cursors, layout guides, show outlines, remove fill, remove stroke, send to back/forward, bring to
  front/backward, adjust list indentation, font size/weight/letter spacing/line height, type ellipsis,
  type `@`, type `\`, add code block, use cursor chat, open quick actions, paste to replace, select parent.
- Figma **notifies the user of a mismatch** between the OS keyboard layout and the Figma setting.
- The Figma desktop app can read the OS layout identifier (e.g. `com.apple.keylayout.ABC`,
  `org.sil.ukelele`). [ENGINEERING-DISCLOSED — "Behind the scenes: international keyboard shortcuts"]

Critically: **Figma does not offer user-assignable shortcuts.** The model is *layout selection*, not
*binding customisation*. [DOCUMENTED / INFERRED from the absence of any rebinding UI in the docs]

### Contextual actions

- **Actions menu**: `Cmd/Ctrl + /`. A searchable command palette that exposes every action by name.
  This is the escape hatch for anything without a shortcut, and the model for discoverability.
  [DOCUMENTED]
- **F6 / Ctrl+F6** focuses the toolbar; arrow keys then navigate it. [DOCUMENTED]
- **Keyboard box selection**: `Option+Space` (Mac) / `Ctrl+Space` (Win) puts a pink cursor on canvas;
  arrows position it, `Return` selects, `Tab`/`Shift+Tab` walks children, `Cmd/Ctrl`+arrows resize the
  box, `Shift`+arrows change adjustment size, `Esc` exits. [DOCUMENTED]
- **Crosshair placement mode**: enable a tool, then `Return/Enter` places the object. [DOCUMENTED]
- **Focus model**: `Main menu → Preferences → Accessibility settings → Adapt content for screen readers`
  adapts canvas content for assistive tech. [DOCUMENTED]

## Rendering / Performance

- **Figma's renderer is WebGL, migrated to WebGPU (announced September 2025).** [DOCUMENTED — Figma
  Blog, "Figma Rendering: Powered by WebGPU"]; [ENGINEERING-DISCLOSED] the post title and abstract
  state the migration unlocked new performance optimisation opportunities. The post body did not render
  in the retrieval used, so specific techniques are **Unknown** from that source.
- Historical context: Figma's original engineering position is that browsers expose a high-performance
  GPU compositor but no way to hook the rendering algorithm, so Figma built its own C++/WASM renderer
  with its own scene graph. [ENGINEERING-DISCLOSED — "Building a professional design tool on the web",
  2015] and [THIRD-PARTY — "A Tour of the C++ Engine which Powers That Design MMO", conference talk,
  which states: "The renderer, scene graph data model, and other compute-intensive [systems are C++]"
  and "Figma's browser client code is primarily comprised of C++ and TypeScript."]
- **Scene graph exists as a named concept** in public Figma material. [ENGINEERING-DISCLOSED]
- Figma maintains a dedicated performance-testing framework; "Keeping Figma Fast" (Aug 2023) is an
  engineering post about that harness, driven by a laptop crashing in an empty office. [ENGINEERING-DISCLOSED]
- Explicit performance engineering surface in the product: snap thresholds are zoom-aware; text and
  effects have LOD; the pixel grid is a deliberate visual affordance for zoom level.

[INFERRED] Figma's architecture separates (a) a document model, (b) a scene graph / render tree
optimised for GPU submission, and (c) a UI layer. The observable consequence for Spool is that a
design-document hierarchy must not be assumed to equal the view hierarchy used for rendering.

## Prototyping

Prototyping in Figma is **document metadata attached to nodes**, plus a flow graph.

**Interaction = trigger + action + animation.**
- Triggers (documented families): on click, on hover / mouse enter, mouse leave, mouse down, mouse up,
  after delay, while pressing keys (key combinations), while dragging, on scroll, on media end.
  [DOCUMENTED families; the exhaustive list is in "Connect your prototype"]
- Actions (fully DOCUMENTED in "Prototype actions"): **Navigate to**, **Back**, **Set variable**,
  **Set variable mode**, **Conditional** (if/else), **Scroll to**, **Open link**, **Open overlay**,
  **Close overlay**, **Swap overlay**, **Play/pause video**, **Mute/unmute video**, **Set to specific
  time**, **Jump forward/backward in time**, **Change to** (switch variant in interactive components).
- Animations: **Smart Animate**, plus dissolve/instant/move-in/slide-in/push and easing/timing options.
- Overflow behaviour enables scrolling of frame contents. Because auto layout parents are content-driven,
  "To replicate scrolling overflow you will need to put the auto layout inside a regular frame."
  [DOCUMENTED]
- Variables participate in prototyping: string variables can switch **variant instances**; number
  variables drive Motion animation distance/scale/rotation/size/opacity; timing and easing variables drive
  duration and curve. [DOCUMENTED]
- Presentation mode; long frames scroll by default.
- `Swap overlay` deliberately **does not** add the frame to prototype history — a documented, subtle
  difference from `Navigate to`. [DOCUMENTED]

[INFERRED] Prototyping in Figma is best modelled as **two layers**: (1) per-node interaction records
that reference targets, and (2) a flow graph whose nodes are frames and whose edges are connections.
It is *not* stored in a separate document. The existence of `Conditional` and `Set variable` implies a
small execution environment over document state.

[INFERRED] Figma's trajectory is from *raster generation* → *code generation* → back to *native

### What the evidence actually supports

1. **Frame is the universal container** and groups are not. [DOCUMENTED]
2. **Selection has a depth/scope stack**, not just a set of ids. [INFERRED from documented
   click-parent / double-click-descend / Shift+Enter-ascend behaviour]

4. **Layout is multi-modal with explicit opt-out per child.** [DOCUMENTED]
5. **Styles and variables are two different indirection systems** with different composition rules.
   [DOCUMENTED]

   override/reset/detach/variant behaviour]

   execution environment. [INFERRED from documented actions]

## Important Interaction Conventions

These are the conventions so widely copied that Spool should treat them as the "default dialect".

- Selection outline is a **single accent-coloured box**; the parent gets a **secondary/dashed** box.
- Click selects the **container**, double-click descends. This is the single most-copied convention in
  design tooling.
- `Enter` descends, `Escape` ascends/cancels. `Escape` is universal cancel.
- `Shift` is almost always "constrain" (axis lock, aspect lock, angle snap) or "add to selection".
- `Alt`/`Option` is almost always "duplicate while dragging", "ignore constraints", or "resize from
  centre" — the *modifier-with-memory* pattern.
- `Cmd/Ctrl` is almost always "deep select", "paste in place", or "temporarily bypass a snap/constraint".
- Small nudge / big nudge is a first-class user preference, not a hardcoded constant.
- Every tool must work with a click and with a drag, and the two produce *different* results (click =
  default size / auto size, drag = explicit bounds).

## Changelog / Evolution

Product evolution is the strongest architectural evidence available, because mature products split
concepts when one concept had to carry two incompatible meanings.

| Change | Signal |
|---|---|
| **"absolute position" renamed to "Ignore auto layout"** | [DOCUMENTED] The original name implied the concept was about coordinates. The new name admits it is about **escaping a layout flow**. Figma had to rename a core concept once layout systems coexisted. |
| Auto layout added **Wrap**, then clarified **"Vertical wrap is not a masonry layout"** | [DOCUMENTED] A feature shipped with an ambiguous name and required a disambiguating clarification. Signals that flow semantics need explicit specification. |
| **Variables** introduced as a separate system from styles, with **collections**, **groups**, **modes**, and **aliasing** | [DOCUMENTED] Five separate concepts added to solve problems styles could not. The doc explicitly explains *when to use which*. |
| **Min/Max dimensions** added alongside Fixed/Hug/Fill | [DOCUMENTED] Sizing modes were insufficient; the model became a mode *plus* clamp bounds. |
| **Components + Instances + Variants + Component properties + Instance swap** | [DOCUMENTED] Reuse went from a boolean "is a component" to a five-part system. Instance swap is explicitly recommended as the way to vary icons — implying the original component model could not parameterise a *type*. |
| **Figma Sites / Buzz / Slides / Make / Motion / Dev Mode** | [DOCUMENTED] The editor was split into surfaces, and the same canvas now belongs to several. Implies a shared document/runtime with multiple presentations. |
| **First Draft (layers) → Make (code) → Design Agent (layers again)** | [DOCUMENTED] The AI abstraction level was tried at "native layers" and at "code", and has returned to "native layers" for the canvas. |
| **MCP Server** | [DOCUMENTED] The document is being exposed to external agents at the *operation* level, not just via plugins. |
| **Keyboard box selection + crosshair placement + 16 keyboard layouts** | [DOCUMENTED] Accessibility investment long after shortcuts shipped. Keyboard controls "cannot be disabled". |
| **Branching and merging** | [DOCUMENTED] The single-document model became insufficient for parallel design work. |
| **"Adapt content for screen readers"** | [DOCUMENTED] Canvas content became a first-class accessibility surface. |
| Groups explicitly excluded from constraints | [DOCUMENTED] Reveals that group bounds are derived, which forces this restriction. |
